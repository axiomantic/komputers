# Kompute-rs Glossary

**Version:** 1.0
**Purpose:** Definitive reference for terminology, concepts, and specialized vocabulary used throughout the Kompute-rs project.

---

## Core GPU Computing Concepts

### **Algorithm**
A compute shader program and its associated parameter bindings in Kompute. Represents a GPU kernel that can process data in parallel. In Kompute-rs, wrapped as a safe Rust struct with RAII resource management.

### **Binding**
The process of associating tensor data with shader parameters. Specifies which GPU memory buffers correspond to which shader input/output variables.

### **Buffer**
Low-level GPU memory allocation used to store data. Tensors are built on top of buffers with additional type safety and management.

### **Command Buffer**
Vulkan construct that records GPU commands for later execution. In Kompute, managed through Sequences for batched operations.

### **Compute Pipeline**
Vulkan graphics pipeline configured for compute shaders rather than rendering. Defines the execution environment for GPU compute operations.

### **Compute Shader**
GPU program written in GLSL or HLSL and compiled to SPIR-V bytecode. Executes in parallel across many GPU cores to process data efficiently.

## Kompute-Specific Terms

### **Manager**
Central orchestrator in Kompute responsible for:
- GPU device management and selection
- Vulkan instance lifecycle
- Resource allocation and cleanup
- Sequence and tensor factory methods

### **Sequence**
Container for batched GPU operations in Kompute. Records multiple operations for efficient execution as a single command buffer. Supports both synchronous and asynchronous execution modes.

### **Tensor**
Structured data container for GPU operations. Handles:
- Host-device memory synchronization
- Type-safe data access
- Automatic resource cleanup
- Multi-dimensional data layout

## Rust-Specific Architecture Terms

### **FFI Layer (kompute-sys)**
Low-level Foreign Function Interface providing unsafe bindings to the Kompute C++ library. Contains:
- Raw C++ function bindings generated by bindgen
- Unsafe wrapper functions for C++ class methods
- Dynamic library loading and linking logic

### **Safe Wrapper Layer**
Middle layer providing memory-safe abstractions over the FFI layer. Implements:
- RAII patterns for automatic resource cleanup
- Safe interfaces that prevent use-after-free bugs
- Rust error types converted from C++ exceptions
- Lifetime management for GPU resources

### **Idiomatic API Layer**
High-level public API following Rust conventions and best practices:
- Builder patterns for complex object construction
- Generic types with trait bounds
- Iterator-based APIs where appropriate
- Integration with Rust's async ecosystem

### **Zero-Cost Abstraction**
Rust design principle where high-level abstractions compile to the same efficient code as low-level implementations. Kompute-rs aims to provide ergonomic APIs with minimal performance overhead.

## Vulkan and GPU Terms

### **Device**
Physical GPU hardware or software implementation. Vulkan distinguishes between:
- **Physical Device**: Actual GPU hardware
- **Logical Device**: Software interface to access GPU capabilities

### **Instance**
Top-level Vulkan object representing connection to the Vulkan API. Required for all Vulkan operations and device enumeration.

### **Queue Family**
Group of command queues with similar capabilities. Compute operations typically use queues from compute-capable families.

### **SPIR-V**
Standard Portable Intermediate Representation for Vulkan shaders. Binary format that compute shaders are compiled to before GPU execution.

### **Vulkan**
Low-level graphics and compute API providing explicit control over GPU resources. Foundation for Kompute's cross-platform GPU computing capabilities.

### **Workgroup**
Basic unit of parallel execution in compute shaders. Threads within a workgroup can synchronize and share local memory.

## Memory Management Terms

### **Host Memory**
System RAM accessible by the CPU. Data typically starts in host memory before being transferred to the GPU.

### **Device Memory**
GPU-local memory optimized for high-bandwidth access by GPU cores. Usually faster than host memory for GPU operations but not directly accessible by CPU.

### **Memory Mapping**
Process of making GPU memory accessible to the CPU through virtual memory mapping. Enables direct CPU access without explicit copy operations.

### **RAII (Resource Acquisition Is Initialization)**
C++ and Rust design pattern where resource lifetime is tied to object lifetime. Ensures automatic cleanup when objects go out of scope.

### **Staging Buffer**
Intermediate GPU memory buffer used to transfer data between host and device memory. Optimizes transfer performance for large datasets.

## Error Handling Terms

### **KomputeError**
Primary error type in Kompute-rs encompassing all possible failure modes:
- GPU initialization failures
- Memory allocation errors
- Vulkan API errors
- Invalid parameter errors
- Shader compilation failures

### **Result Type**
Rust's standard error handling mechanism. All Kompute-rs APIs return `Result<T, KomputeError>` for explicit error handling.

### **Error Context**
Additional information attached to errors to aid debugging. Includes operation context, parameter values, and system state.

## Performance and Optimization Terms

### **Batching**
Grouping multiple GPU operations into a single command buffer for efficient execution. Reduces GPU command submission overhead.

### **Memory Bandwidth**
Rate at which data can be transferred between different memory hierarchies. Critical factor in GPU performance optimization.

### **Memory Coalescing**
GPU memory access pattern where adjacent threads access adjacent memory locations. Enables efficient memory throughput.

### **Occupancy**
Measure of how efficiently GPU compute units are utilized. Higher occupancy generally leads to better performance.

### **Pipeline Stall**
Condition where GPU execution pipeline cannot proceed due to resource conflicts or dependencies. Should be minimized for optimal performance.

## Testing and Quality Assurance Terms

### **Integration Test**
Test that validates component interactions and complete workflows using real GPU operations rather than mocks.

### **Mock GPU**
Software simulation of GPU operations used in unit tests where real GPU access is not available or appropriate.

### **Performance Benchmark**
Standardized test measuring execution time, memory usage, or throughput. Used to validate performance requirements and detect regressions.

### **Quality Gate**
Automated check that must pass before code changes are accepted. Includes linting, type checking, test coverage, and security scanning.

### **Unit Test**
Test that validates individual component behavior in isolation from other system components.

## Development Workflow Terms

### **Component**
Self-contained unit of functionality with clearly defined responsibilities and interfaces. Tracked individually in the STATUS_MANIFEST.yaml.

### **Dependency Chain**
Ordered sequence of components where each component depends on the completion of previous components.

### **Status Manifest**
YAML file tracking the implementation status of all project components, their dependencies, and completion evidence.

### **Summoning**
Process of generating a detailed implementation plan for a specific component and immediately implementing it following established patterns.

## Architectural Patterns

### **Builder Pattern**
Creational design pattern providing fluent interface for constructing complex objects with optional parameters and validation.

### **Factory Pattern**
Creational pattern where objects are created through factory methods rather than direct constructors. Used in Manager class for creating tensors and sequences.

### **Observer Pattern**
Behavioral pattern for notifying interested parties of state changes. Potentially useful for async GPU operation completion notifications.

### **Three-Layer Architecture**
Kompute-rs architectural pattern separating:
1. FFI Layer (unsafe C++ bindings)
2. Safe Wrapper Layer (memory-safe abstractions)
3. Idiomatic API Layer (Rust conventions)

## Domain-Specific Acronyms

### **API**
Application Programming Interface - the public interface exposed to users of the library.

### **FFI**
Foreign Function Interface - mechanism for calling functions written in other languages (C++ in this case).

### **GPU**
Graphics Processing Unit - specialized hardware for parallel computation.

### **GPGPU**
General-Purpose computing on Graphics Processing Units - using GPU hardware for non-graphics computational tasks.

### **RAII**
Resource Acquisition Is Initialization - automatic resource management pattern.

### **SPIR-V**
Standard Portable Intermediate Representation for Vulkan - shader bytecode format.

### **TDD**
Test-Driven Development - methodology where tests are written before implementation code.

## Platform and Compatibility Terms

### **Cross-Platform**
Software that runs on multiple operating systems (Linux, Windows, macOS) without modification.

### **Cross-Vendor**
GPU software that works with hardware from different manufacturers (AMD, NVIDIA, Intel, Qualcomm).

### **Bindgen**
Rust tool for automatically generating FFI bindings from C/C++ header files.

### **CMake**
Cross-platform build system used by the Kompute C++ library.
